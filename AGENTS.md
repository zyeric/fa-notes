# Agent instructions — fa-notes

This repository is a source-backed learning and audit record for
FlashAttention. Preserve the bridge from mathematical semantics to physical
execution; source-code transcription alone is not the deliverable.

## Document ownership

- `docs/notes/` is the source of truth.
- `docs/slides/` contains manually maintained visual reading surfaces.
- `docs/notes.html` is generated by `python3 docs/render_notes.py`.
- `docs/index.html` is the public navigation and cross-generation entry point.

When a conclusion changes, update the owning Markdown note first, then any
slide or landing-page claim that depends on it, and finally regenerate
`docs/notes.html`.

## Evidence discipline

- Pin the paper, source revision, architecture, dtype, shape, and kernel path
  behind an implementation claim.
- Distinguish mathematical facts, source-backed implementation observations,
  hardware inferences, paper-reported measurements, and local measurements.
- Do not turn CPU-only source reasoning into a measured performance or bitwise
  determinism claim.
- State ownership, residence, lifetime, reduction order, and synchronization
  for every important intermediate.
- Keep generic GPU background in `gpu-hardware-notes`; link it rather than
  maintaining a conflicting second copy here.

## Scope discipline

FA1 through FA4 ordinary training attention is the current core. FlashMLA,
linear attention, paged/decode attention, inference scheduling, batch
invariance, and model-specific large-head-dimension paths need explicit scope
decisions before being added.

## Validation

After documentation changes, run:

```bash
python3 docs/render_notes.py
git diff --check
```

Also validate links and HTML structure. Browser rendering remains necessary
for accepting slide layout changes.
