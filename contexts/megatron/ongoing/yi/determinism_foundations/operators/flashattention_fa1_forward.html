为什么这个例子有用？

  • Q/K/V/O 本身各约 64 MiB，线性随 N 增长；
  • score/probability 每个 head 有约 6710 万个元素，随 N² 增长；

thread、lane、register 是什么关系？

  • warp：SM scheduler 的基本 instruction-issue unit；32 threads 通常执行同一条 warp instruction；
  • lane：thread 在 warp 内的编号 0…31；这里可把 lane 和 CUDA thread instance 对应起来；
  • register：每个 thread 私有的逻辑状态；pointer、loop index、load result、MMA fragment 都可在 registers；
  • 物理 register file 属于 SM，但 compiler 为每个 resident thread 分配互不混淆的 register state。

“tile 在 registers”表示 tile 元素分散在很多 lanes 的私有 registers 中，不是一个 thread 存整块，也不是所有 thread 各存一份。

先 admission，后逐 warp issue

  1. CTA admission 时一次性预留 threads/warps、registers、shared memory、block/barrier state；
  2. 资源都放得下，CTA 才能 resident；普通 shared memory allocation 在 CTAs 间互相隔离；
  3. resident 后，scheduler 可以交错发射 A/B/C 的 ready warps；
  4. 某个 CTA 所有 warps 完成后，资源释放，pending CTA 才可进入。

A100/H100 最多 64 resident warps/SM 是 capacity limit，不代表 64 warps 同时执行；实际 resident CTA 数还取 registers、smem、block slots 等约束的最小值。

为什么这个 reduction 可重复？

  • later MMA 读取 previous accumulator；
  • compiled instruction stream 固定 D-chunk 次序；
  • WARPS_K=1，没有多个 warps 为同一 score 发布独立 D-partials；
  • warp 可暂停或与别的 warp interleave，但不能越过 true dependency。

这只支持固定 binary/architecture 的 repeatability；不证明 fused vs unfused、D64 vs D128、SM80 vs SM90 bits 相同。

Multi-head, varlen, and dropout · what changes?

Multi-head

每个 head 是独立 attention matrix；增加 grid CTAs，不引入 cross-head forward reduction。

v1.0.9 studied path expects equal Q/K/V head count；MQA/GQA outside scope。

Packed varlen

cu_seqlens 给 packed offsets；predicates / early exits 处理真实长度。

改变地址、active work 与 load balance；不改变 online recurrence 或 O-row owner。

Dropout

softmax 后对 P 应用 keep mask；normalizer 不变，value path 改变。

repeatability 额外要求 Philox seed、offset 与 logical-coordinate mapping 一致。

Probe 边界：padded / unused LSE bytes 不一定是 semantic output；fully masked rows 的约定也必须从 source 定义，不能直接把整个 workspace bytewise compare。
