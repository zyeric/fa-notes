Original FA1 paper
B × H = 32 CTAs

one CTA per head；长序列不会自动增加 grid workers。

FA1 illustrative R=4
grid = B × H × R = 128 CTAs

每个 head 只有 4 个 CTA；一个 CTA round-robin owns many 16-row Q tiles。

R is host-selected and not universally 4；这里仅用于解释 granularity。

FA2 B_M=128
grid = 64 × B × H = 2048 CTAs

每个 head 有 8192/128=64 个 independent Q-block CTAs；每个 CTA 完成自己的全部 K/V reduction。

32 → 128 → 2048 展示的是 worker granularity；FA2 不是把同一个 O row 拆给 64 个 CTA。

Advantage 1 · more useful CTA work when B×H is small

FA1 risk

当 batch×heads 较小，少量 heavy CTAs 可能形成不足或不整齐的 SM waves。

FA2 response

把 Q sequence 暴露为一个 CTA per row block，GPU scheduler 有更多 independent work units。

Boundary

更多 CTA 不自动等于更快；occupancy、resource footprint、causal imbalance 与 launch overhead 仍要 profile。

“Reads less” is not one number · count instructions, cache traffic, and HBM separately

Logical access swap

paper-style FA1: K/V reuse inside head CTA revisit Q + mutable running O/state FA2: load Q once; retain running state every Q CTA requests its K/V tiles

只数 Q/K/V reads，FA2 未必显著更少；加上 running-O read/write，FA2 的总 traffic 更有优势。

Three physical ledgers

global load/store instructions→L2 sectors / hit rate→HBM bytes

不同 Q CTAs 的重复 K/V global loads 可能命中 L2；不能把“每 CTA load”直接等同于“每次从 HBM DRAM 读”。

FA1 v1.0.9 的 R 个 split CTAs 也会各自请求 K/V，因此 paper baseline 与 source baseline 再次不同。

FA2 的关键不是所有 reads 都更少，而是用 cacheable read-only duplication 换掉 mutable-state round trips。

Nuance · “no inter-warp O reduction” does not mean “no reduction or sync”

Softmax remains

每个 score row 仍要对 B_N columns 做 max/sum；source 使用 per-thread work + fixed four-lane-group all-reduces。

CTA barriers remain

all warps share Q/K/V buffers；buffer generation reuse 与 epilogue shared handoff 都需要 synchronization。

MMA chains remain

每个 output accumulator 仍沿 D 或 B_N reduction 维执行 dependent MMA instruction chain。

FA2 删除的是一个特定的cross-warp numeric combine，不是删除所有依赖。

What FA2 teaches beyond attention

1 · Loop interchange is physical

它同时改变 global traffic、state lifetime、CTA count 与 FP association。

2 · Prefer complete owners

把 output axis 分给 workers，通常比切 reduction axis 更少 combine 与 race obligations。

3 · Read duplication can win

重复 read-only input 可能比反复发布 mutable partial state 更便宜。

4 · Copy path supports compute design

async movement 的价值在于支撑 larger live state 与 overlap，不应孤立分析。

5 · More parallel is scoped

worker count 增加不消除 CTA imbalance、resource limits 或 tail waves。

6 · Re-prove determinism

性能重写后重新画 ownership/combine graph；不能继承旧 kernel 的结论。
