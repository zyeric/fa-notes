计算单元为什么离不开 memory path？

  • 图中下方六个小框：全部是“放大一个 SM”之后的内部组件，不在 SM 外面；108 个 SM 各有自己的对应资源。
  • Tensor Cores：高吞吐执行 matrix multiply-accumulate；输入 fragments 和 accumulator state 必须先到片上 operand path。
  • CUDA-core / scalar-vector paths：地址、普通算术、max/sum、类型转换和控制逻辑。
  • SFUs：协助 exp/reciprocal 等特殊函数。
  • Load/store units：在 registers、shared/L1、L2、HBM 之间服务 memory instructions。

峰值 Tensor Core FLOPs 只有在 operands 及时到达时才有意义；喂不饱计算单元时，kernel 等的是 data，不是乘法器。

Register is physical storage

每个 lane/thread 的 register 都在 SM register file 中，lane-private。fetch、pointer、predicate、fragment、accumulator 只是不同 values/lifetimes；GPU 没有一块独立的“fragment memory”。

Fragment is a logical contract

某条 MMA 规定 32 lanes 各自要在若干 registers 中提供哪些 A/B elements，并在哪些 FP32 registers 接收 C/D elements。所有 lane tuples 合起来才是一块矩阵 fragment；单 lane 的 elements 不保证在原矩阵中形成完整或连续的一行/列。
